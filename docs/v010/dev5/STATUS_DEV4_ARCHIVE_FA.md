# مدیریت زندگی رها — ۰٫۱۰٫۰-dev.4+۲۰ — اصلاحات ممیزی

این نسخه ایرادهای تأییدشدهٔ گزارش ممیزی را اصلاح می‌کند. نسخه توسعه‌ای است؛ «امنیت کامل»، پایان تمام درخواست‌های قبلی یا انتشار نهایی فروشگاهی اعلام نمی‌شود. مبنا سورس کامل dev.3+19 است.

## اصلاحات
- صف سینک: تغییر بیش از حد بزرگ در جدول مستقل sync_quarantine علامت‌گذاری می‌شود؛ اصل رکورد و تغییر حذف نمی‌شوند و رکوردهای سالم و ویرایش کوچک‌تر بعدی ارسال می‌شوند. صفحه جزئیات، رکورد مربوط را برای اصلاح باز می‌کند.
- مالی: ورودی مبلغ مستقیماً از متن به عدد صحیح تبدیل می‌شود؛ ۰٫۵۷۵ به ۵۸ صدم تبدیل می‌شود. فرم تراکنش، حساب، اقساط، ویرایش عمومی و خروجی CSV از مسیر صحیح استفاده می‌کنند. مقدار minor ذخیره‌شده مرجع است؛ double فقط برای سازگاری API قدیمی و نمایش باقی است. مقیاس تاریخی ۱۰۰ برای ارزها تغییر نکرده است. مبالغ قدیمی که قبلاً غلط گرد شده‌اند بدون تشخیص مقدار موردنظر کاربر خودکار تغییر داده نمی‌شوند.
- موجودی چندارزی: درخواست یک عدد تجمیعی خطا می‌دهد؛ صفحات اصلی و گزارش همچنان مبالغ را به تفکیک ارز نمایش می‌دهند.
- بازیابی بکاپ: نسخه علتاً جدیدتر اعمال و برای سینک صف‌بندی می‌شود؛ نسخه محلی جدیدتر حفظ می‌شود؛ فقط تغییر مستقل یا ساعت برابر با محتوای متفاوت، تعارض می‌سازد. حذف جدیدتر نیز اعمال می‌شود.
- ذخیره‌سازی: عملیات شکست‌خورده قابلیت تلاش مجدد دارد؛ flush پیش از سینک/بکاپ آن را دوباره اجرا می‌کند. موفقیت یک عملیات دیگر خطای ذخیرهٔ ناموفق را پنهان نمی‌کند. شکست پایدار و خطای بارگذاری همچنان مانع عبور داده ناسالم می‌شوند.
- تراکنش چندبخشی: مبنای مقایسهٔ حافظه همراه شکست تراکنش عقب برمی‌گردد؛ تلاش بعدی واقعاً داده را ذخیره می‌کند.
- تولد ۳۰ اسفند و ۲۹ فوریه: در سال غیرکبیسه آخرین روز همان ماه محسوب می‌شود؛ در سال کبیسه روز اصلی حفظ می‌شود.
- منطقه زمانی: پیش از هماهنگ‌سازی اعلان‌ها دوباره خوانده می‌شود؛ هنگام بازگشت به اپ و تغییر منطقه در اجرای فعال، برنامهٔ موعدها تازه می‌شود. در شکست تشخیص، آخرین منطقه معتبر حفظ و خطا گزارش می‌شود.
- شمارندهٔ انتظار: اسکوپ اتصال اصلی و قرنطینه را رعایت می‌کند؛ تغییر انتخاب بخش‌ها نیز شمارنده را تازه می‌کند.
- مهاجرت SQLite نسخه ۸: جدول‌های مفقود و ستون‌های جاافتاده به‌صورت غیرمخرب تکمیل می‌شوند.

## امنیت سرور و نشست
- CORS پیش‌فرض بسته است؛ مبدأهای مجاز باید دقیقاً در cors_origin تعیین شوند. درخواست native بدون Origin پشتیبانی می‌شود. مقدار * دیگر مرورگرها را مجاز نمی‌کند.
- HSTS فقط برای HTTPS مستقیم تنظیم می‌شود؛ تنظیم TLS/HSTS در پراکسی مورداعتماد مسئولیت میزبان است.
- محدودسازی اتمیک درخواست با قفل فایل برای API، حساب و احراز هویت؛ آزمون ۲۴ درخواست هم‌زمان نشان داد سقف ۱۰ دور زده نمی‌شود. پوشه rate_limits باید خارج از public و قابل نوشتن برای PHP باشد.
- نشست‌های جدید پیش‌فرض ۷ روزه‌اند، قابل تنظیم بین ۱ تا ۳۰ روز. نوسازی نشست، توکن قبلی را باطل می‌کند. «خروج از همهٔ دستگاه‌ها» نشست‌های همان حساب را حذف می‌کند؛ حساب دیگر فعال می‌ماند.
- شناسه حساب همکاری از تنظیمات قدیمی به Secure Storage منتقل می‌شود. پاسخ ۴۰۱ نشست محلی را پاک می‌کند و ورود دوباره می‌خواهد؛ پیام‌های صف حذف نمی‌شوند.

## آزمون همین نسخه
- Flutter analyze: بدون خطا، هشدار یا info.
- ۱۲۵ تست Flutter موفق، شامل ۱۳ تست جدید نسبت به dev.3. تست‌های UI موجود در عرض‌های موبایل/تبلت/دسکتاپ با متن بزرگ نیز اجرا شدند.
- ارتقا از ساختارهای بازسازی‌شده v4/v5/v6/v7: حفظ داده و برابری ستون‌ها با دیتابیس تازه. این fixtureها جای دیتابیس واقعی نصب‌شدهٔ کاربران را نمی‌گیرند.
- PHP 8.3: بررسی نحوی همه فایل‌ها، تست رمز عبور، پروتکل، بکاپ و امنیت موفق.
- آزمون HTTP واقعی با MariaDB 10.11: تفکیک حساب، اسکوپ انتخابی، ACK دقیق، تعارض علّی، پیام تکراری، مجوز اشتراک، لغو دسترسی، نوسازی توکن و خروج همه دستگاه‌ها موفق.
- سه تست Python و خواندن YAML تمام گردش‌های CI موفق.
- ساخت Web release موفق. گزارش‌های خام در validation/dev4-* هستند. ساخت وب با Client ID ناشر انجام نشده؛ OAuth نیاز به پیکربندی رسمی ناشر دارد.
- تست باگ صف همکاری، ادعای گم‌شدن پیام را در مسیر فعلی رد کرد؛ قفل ترتیبی آن حفظ شد. share() و شاخه مهاجرت from==6 به‌عنوان باگ تغییر نکردند.
