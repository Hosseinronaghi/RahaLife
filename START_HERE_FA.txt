مدیریت زندگی رها — 0.9.0+16 — بستهٔ بررسی

اول RELEASE_0.9_FA.md را بخوانید؛ فهرست قابلیت‌های انجام‌شده و باقی‌مانده در آن دقیقاً جدا شده است.
مبنای پک تغییرات: Raha-Life-v0.8.0-CI-Fix

GitHub:
1) از پروژهٔ فعلی خود یک کپی نگه دارید.
2) ZIP کامل را باز کنید. ریشهٔ درست پوشه‌ای است که pubspec.yaml و پوشه‌های lib، tool و .github در آن هستند.
3) محتوای همین ریشه را روی ریشهٔ مخزن RahaLife جایگزین کنید؛ lib را داخل lib/app نریزید.
4) با GitHub Desktop کل تغییرات را مرور و Commit و Push کنید. محدودیت ۱۰۰ فایلِ فرم آپلود وب در این روش مطرح نیست.
5) اگر فقط پک Changed-Files را استفاده می‌کنید، مسیرهای داخل ZIP باید از ریشهٔ همان نسخهٔ پایه جایگزین شوند. خود فایل ZIP را به‌عنوان سورس آپلود نکنید؛ GitHub آن را خودکار استخراج نمی‌کند.
6) عنوان و متن Commit در COMMIT_MESSAGE.txt آماده است.
7) در Actions گردش Build Raha Life را اجرا کنید. سبزشدن Server protocol and account tests به‌تنهایی APK تولید نمی‌کند.
8) پس از موفقیت ساخت، فایل‌ها در Artifacts همان اجرای Build Raha Life قرار می‌گیرند. خروجی سیستم‌های اضافه در Build Raha Life Extended Platforms است.

نصب روی نسخهٔ قبلی Android:
- applicationId و گواهی امضای قبلی باید یکسان باشند و versionCode بیشتر باشد.
- شمارهٔ فعلی 16 است؛ اگر نسخهٔ نصب‌شده شمارهٔ بالاتری دارد، نسخه باید با شمارهٔ بیشتر ساخته شود.
- چهار Secret مربوط به keystore در راهنمای امضای موجود پروژه توضیح داده شده‌اند: RAHA_ANDROID_KEYSTORE_BASE64، RAHA_ANDROID_KEYSTORE_PASSWORD، RAHA_ANDROID_KEY_ALIAS، RAHA_ANDROID_KEY_PASSWORD.
- از همان keystore قبلی استفاده کنید. کلید موقت GitHub هر اجرا ممکن است متفاوت باشد؛ از آن نمی‌توان تضمین ارتقا گرفت.
- برای کنترل دو APK: python tool/verify_android_upgrade.py previous.apk new.apk
- ابزار فوق به apkanalyzer و apksigner از Android SDK نیاز دارد؛ آزمون نصب و حفظ داده روی گوشی همچنان لازم است. برای رفع خطای امضا، برنامهٔ دارای اطلاعات را بی‌بررسی حذف نکنید.

هاست اشتراکی:
- برای نصب جدید server/shared-hosting/install.sql؛ برای نسخهٔ 0.8 موجود، پس از بکاپ و توقف نوشتن، upgrade_v0.9.sql را یک بار اجرا کنید.
- فایل‌های PHP را یکجا به‌روز کنید. فقط public/ باید زیر ریشهٔ عمومی وب قرار گیرد؛ تنظیمات و storage خصوصی بمانند.
- جزئیات در server/shared-hosting/README.md است.
- صفحهٔ «داده و همگام‌سازی» > آیکون تنظیم بخش‌ها، انتخاب بخش‌های اتصال موجود را تغییر می‌دهد.
- «ارتباطات» > آیکون شبکه، اتصال آزمایشی Matrix/Mastodon را باز می‌کند. وضعیت رمزنگاری را قبل از استفاده بخوانید.

بستهٔ Web جداگانه، خروجی وب است و جایگزین سورس مخزن نیست. آن را روی مسیر HTTPS وب‌سرور منتشر کنید؛ روی دامنهٔ قبلی برای حفظ دسترسی به داده‌های مرورگر آزمایش کنید.

در صورت استفاده از فرم آپلود وب GitHub و سقف ۱۰۰ فایل:
آرشیو Web-Upload-Batches شامل چند ZIP کمتر از ۱۰۰ فایل است. هر بخش را جداگانه باز کنید و محتوایش را با حفظ مسیرها به ریشهٔ مخزن بدهید؛ صبر کنید همهٔ بخش‌ها آپلود شوند و سپس گردش ساخت را از آخرین Commit اجرا کنید. سبزشدن نسخهٔ میانی معیار پذیرش نیست. اگر پوشهٔ .github مخفی است، نمایش فایل‌های مخفی را فعال کنید یا فایل‌های گردش کار را جداگانه در همان مسیر دقیق جایگزین کنید.
